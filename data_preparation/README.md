\# Пайплайн подготовки датасета конвейерной ленты



Набор скриптов для построения датасета конвейерной ленты в формате,

совместимом с MVTec AD, из исходных фотографий, сделанных

на производственной площадке. Используется для адаптации метода

OrthoAD под собственную категорию `belt`.



\## Обоснование структуры пайплайна



Метод OrthoAD (как и его предшественник PaDiM) строит \*\*локальные\*\*

статистические модели признаков для каждой пространственной позиции

карты признаков. Это требует, чтобы все обучающие и тестовые образцы

были \*\*пространственно согласованы\*\* — то есть лента в кадре должна

занимать одно и то же положение, иначе локальные распределения

смешаются и метод деградирует. По этой причине пайплайн строится

вокруг двух ключевых операций:



1\. \*\*Геометрическое выравнивание\*\* области ленты по четырёхугольной

&#x20;  разметке labelme — перспективное преобразование приводит ленту

&#x20;  к прямоугольной форме и фиксирует её ориентацию.

2\. \*\*Нарезка на патчи фиксированного размера\*\* — позволяет работать

&#x20;  с лентой произвольной длины и обеспечивает единый формат входа

&#x20;  для модели.



Дополнительно к этим двум операциям пайплайн включает автоматическую

фильтрацию патчей по качеству (блики и темнота), group-aware

разбиение на train/test и сборку в финальную структуру каталогов

MVTec AD с пиксельной разметкой дефектов.



\## Структура пайплайна



Пайплайн состоит из двух параллельных веток:



\*\*Ветка А — бездефектные изображения\*\* (формируют train и test/good):

1\. `make\_roi.py` — выравнивание области ленты на бездефектных фото

2\. `make\_patches.py` — нарезка ROI на патчи и фильтрация по качеству

3\. `split\_dataset.py` — разбиение патчей на train/test

4\. `prepare\_belt\_mvtec.py` — пилотная сборка датасета (только норма)



\*\*Ветка Б — дефектные изображения\*\* (формируют test/defect и маски):

5\. `make\_roi\_defects.py` — выравнивание области ленты на дефектных фото

6\. `make\_patches\_defects.py` — нарезка дефектных ROI на патчи

7\. `prepare\_belt\_mvtec\_defect\_test.py` — итоговая сборка с дефектами



\## Ожидаемая структура рабочей папки



Все скрипты используют `Path.cwd()` и формируют пути относительно

\*\*текущей рабочей директории, из которой запускается Python-процесс\*\*.

Это важно: `Path.cwd()` возвращает не папку, где лежит сам скрипт,

а ту папку, откуда вы запустили `python ...`. Поэтому скрипты должны

запускаться из рабочей папки проекта подготовки данных

(не из корня репозитория), и в этой папке должна быть следующая

структура:



```

project\_root/

├── annotations/                  # JSON labelme с меткой 'belt'

│                                 # для бездефектных фото

├── raw\_sample/                   # бездефектные фото (вариант 1)

├── raw\_photos/                   # бездефектные фото (вариант 2)

├── annotations\_defect\_roi/       # JSON labelme с меткой 'belt'

│                                 # для дефектных фото

├── raw\_defect\_sample/            # дефектные фото (вариант 1)

├── raw\_defect\_photos/            # дефектные фото (вариант 2)

└── annotations\_defect\_masks/     # JSON labelme с полигонами

&#x20;                                 # label='defect' (пиксельные маски

&#x20;                                 # дефектов внутри патчей)

```



Скрипты ищут исходные фотографии сначала в `raw\_sample` / `raw\_defect\_sample`,

затем в `raw\_photos` / `raw\_defect\_photos`, что позволяет работать как

с пилотным образцом, так и с полным набором фотографий без правки

кода.



Промежуточные папки (`roi\_aligned`, `patches`, `patches\_all`,

`belt\_dataset\_all`, `roi\_defect\_aligned`, `patches\_defect\_test`,

`belt\_mvtec\_all`, `belt\_mvtec\_defect\_test`) создаются скриптами

автоматически.



\## Порядок запуска



Запускать из рабочей папки проекта подготовки данных,

указывая полный путь до скрипта в репозитории:



```bash

\# === Ветка А: бездефектные изображения ===



\# 1. Выравнивание ROI на бездефектных фото

python <repo>/data\_preparation/make\_roi.py



\# 2. Нарезка выровненных ROI на патчи 512x512 с фильтрацией

python <repo>/data\_preparation/make\_patches.py



\# 3. (Вручную) переименовать patches/ в patches\_all/

\#    или скорректировать имя в split\_dataset.py

ren patches patches\_all



\# 4. Group-aware разбиение на train/test по группам ROI

python <repo>/data\_preparation/split\_dataset.py



\# 5. Сборка пилотного MVTec-датасета (только норма)

python <repo>/data\_preparation/prepare\_belt\_mvtec.py



\# === Ветка Б: дефектные изображения ===



\# 6. Выравнивание ROI на дефектных фото

python <repo>/data\_preparation/make\_roi\_defects.py



\# 7. Нарезка дефектных ROI на патчи 512x512 с фильтрацией

python <repo>/data\_preparation/make\_patches\_defects.py



\# 8. Финальная сборка MVTec-датасета с дефектным test

python <repo>/data\_preparation/prepare\_belt\_mvtec\_defect\_test.py

```



После завершения ветки Б готов финальный датасет

`belt\_mvtec\_defect\_test/`, пригодный для обучения и тестирования

модели OrthoAD.



\## Ключевые параметры обработки



Параметры зафиксированы в начале каждого скрипта и не вынесены

в аргументы командной строки (исследовательский код).



| Параметр              | Значение | Где задаётся                          |

|-----------------------|----------|---------------------------------------|

| Размер патча          | 512×512  | `make\_patches\*.py`                    |

| Страйд нарезки        | 256      | `make\_patches\*.py` (пересечение 50%)  |

| Порог по бликам       | 0.08     | `make\_patches\*.py` (доля ярких пикс.) |

| Порог по темноте      | 8        | `make\_patches\*.py` (mean V в HSV)     |

| Доля тестовой выборки | 0.10     | `split\_dataset.py` (по группам ROI)   |

| Случайный сид         | 42       | `split\_dataset.py`                    |



\### Логика классификации патчей по качеству



В `make\_patches.py` и `make\_patches\_defects.py` каждый патч

переводится в цветовое пространство HSV, после чего:



\- патч помечается как \*\*glare\*\*, если доля пикселей с явным бликом

&#x20; (V > 245, либо V > 225 при S < 80) превышает 8% площади;

\- патч помечается как \*\*dark\*\*, если среднее значение канала V

&#x20; ниже 8;

\- иначе патч признаётся \*\*good\*\* и идёт в финальную выборку.



Имя сохраняемого патча содержит координаты `y, x` его положения

внутри ROI и значения статистик `glare\_ratio`, `mean\_v`,

что позволяет при необходимости вручную проанализировать пограничные

случаи.



\## Защита от утечки данных



Скрипт `split\_dataset.py` выполняет \*\*group-aware\*\* разбиение

на train/test: патчи группируются по имени исходного ROI

(часть имени до маркера `\_y`), и разбиение выполняется

\*\*по группам, а не по отдельным патчам\*\*. Это гарантирует, что

все патчи одного и того же исходного изображения целиком попадают

либо в train, либо в test.



Без такой защиты соседние патчи с одной фотографии (отличающиеся

страйдом 256 пикселей) оказались бы в разных сплитах, и модель

эффективно тестировалась бы на данных, очень близких к обучающим,

что приводило бы к завышенным метрикам качества.



\## Итоговая структура датасета



На выходе пайплайн формирует структуру, совместимую с MVTec AD

и пригодную для загрузки модифицированным `dataset.py` в основном

репозитории:



```

belt\_mvtec\_defect\_test/

└── belt/

&#x20;   ├── train/

&#x20;   │   └── good/                # бездефектные патчи для обучения

&#x20;   ├── test/

&#x20;   │   ├── good/                # бездефектные патчи (норма)

&#x20;   │   └── defect/              # дефектные патчи

&#x20;   └── ground\_truth/

&#x20;       ├── good/                # технический dummy-файл

&#x20;       └── defect/              # бинарные маски дефектов

&#x20;                                # (растеризованные полигоны labelme)

```



Категория `belt` подключается в основном репозитории через

добавление её в список `MVTecAD.categories` (см. коммит

«Подключение собственной категории конвейерной ленты»).



\## Замечания по реализации



\- Все операции чтения и записи изображений выполняются через

&#x20; `np.fromfile` / `cv2.imencode` / `np.ndarray.tofile`, что

&#x20; обеспечивает корректную работу с кириллическими именами файлов

&#x20; на Windows (обычный `cv2.imread` ломается на путях

&#x20; с не-ASCII символами).



\- Для выравнивания области ленты используется перспективное

&#x20; преобразование (`cv2.getPerspectiveTransform` +

&#x20; `cv2.warpPerspective`). Если в разметке указано больше или меньше

&#x20; четырёх вершин, выполняется аппроксимация прямоугольником

&#x20; минимальной площади через `cv2.minAreaRect` с последующим

&#x20; взятием четырёх углов через `cv2.boxPoints`.



\- Для каждой растеризованной маски дефекта проверяется наличие

&#x20; в JSON-файле хотя бы одного полигона (≥3 точек) с меткой `defect`;

&#x20; патчи без такой разметки в `test/defect` не попадают

&#x20; и пропускаются с предупреждением в лог.



\- Дефектным патчам присваивается префикс `defect\_` в имени файла,

&#x20; нормальным тестовым патчам — префикс `normal\_`, что упрощает их

&#x20; визуальное различение при анализе результатов.
